# CLAUDE.md — Studio 1826

Правила работы с этим репозиторием. Держать компактным.

## Границы проекта

Два независимых направления разработки с раздельным контекстом:

1. **Userscript** (`studio1826.user.js` + `studio1826.meta.js`) — расчёт выплат
   администраторов, интерфейс в Bitrix24. Контекст: `docs/userscript/CONTEXT.md`.
2. **Studio1826Updater** (`Studio1826Updater.dmg`, `app.version`) — macOS
   menu-bar приложение для автообновления. Контекст: claude.ai-проект
   "1826Studio" → документ `Studio1826Updater.md`. **Не анализировать,
   не изменять и не обслуживать в рамках задач по userscript.**

Не объединять документацию, историю изменений и контекст этих двух
направлений. Если на границе (например: формат `studio1826.meta.js`,
который читает Updater) обнаружена проблема — фиксировать как внешнюю
зависимость в `docs/userscript/CONTEXT.md`, не трогая код Updater.

## Порядок приоритетов при работе над userscript

1. Безопасность и корректность расчётов — прежде всего.
2. Проверенные дефекты — не доверять статусу «исправлено» в документации
   без чтения актуального кода.
3. Тесты — node:test для чистых функций, обязательна проверка выполнения
   (не заявлять «пройдено» без реального запуска).
4. UX/UI — только после того, как критические проблемы закрыты.

## Правила тестирования

- `node --test tests/` — тесты в `tests/*.test.js`.
- Чистые функции экспортируются из `studio1826.user.js` через
  `module.exports` под guard `typeof module !== 'undefined'` в самом низу
  файла — это не меняет поведение в браузере (Tampermonkey не знает про
  `module`), но даёт доступ к функциям без сборщика и без дублирования кода.
- Функции, завязанные на реальный DOM Bitrix24 (`getTimeAxis`,
  `getCategoryFromBranch`, рендеринг стрелок/панели), тестами не покрываются —
  ограничение зафиксировано в `docs/userscript/CONTEXT.md`.

## Расположение документации

- `docs/userscript/CONTEXT.md` — рабочая память по userscript (единственный
  основной файл контекста). Обновлять после каждого существенного этапа.
- `docs/passes/CONTEXT.md` — рабочая память по отдельному скрипту `studio1826-passes.user.js` (пропуска в Авангарде). Не смешивать с контекстом основного userscript и Updater.
- `README.md` — история аудита и changelog для конечного пользователя
  репозитория, человеко-читаемый. Не дублировать туда рабочие детали из
  CONTEXT.md один-в-один — там краткая версия + ссылка.
- Дополнительные файлы (`SECURITY.md`, `ARCHITECTURE.md`, `UX_UI.md`)
  создавать только когда реально нужны для продолжения работы.

## Требования к итоговым артефактам

- `studio1826.user.js` — всегда полная готовая версия файла, не патч.
- `studio1826.meta.js` — только заголовок `// ==UserScript== ... ==/UserScript==`
  (используется Tampermonkey для лёгкой проверки обновлений через
  `@version` без скачивания всего скрипта). Синхронизировать `@version` с
  `VERSION` в `studio1826.user.js` при каждом релизе.
- Не менять `@updateURL`, `@downloadURL`, `@match` без необходимости —
  от них зависит и автообновление через Tampermonkey, и цепочка
  Studio1826Updater (читает `studio1826.user.js` по тому же raw-URL).
