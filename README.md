# Studio 1826 — Userscript v4.1.5

Userscript для Bitrix24-аккаунта студии 1826. Добавляет расчёт выплат администраторов, панель информации о бронях, копирование оборудования, планирование переноса оборудования на следующий день и настройку темы интерфейса.

---

## Установка

1. Установить [Tampermonkey](https://www.tampermonkey.net/) (Chrome/Firefox/Edge).
2. Перейти по ссылке:
   ```
   https://raw.githubusercontent.com/zinovievilia/studio-1826-installer/main/studio1826.user.js
   ```
3. Tampermonkey предложит установку — подтвердить.

Обновление происходит автоматически через `@updateURL` / `@downloadURL`.

Для пользователей Safari, скрипт устанавливается через UserSripts. Так как там нет `@updateURL` / `@downloadURL`, то скрипт обновляется через Studio1826Updater.dmg

Studio1826Updater.dmg обновляется самостоятельно.

### Подтверждённые ошибки

#### ~~Б-1 (ВЫСОКИЙ): Неверный подсчёт кофе в `compute()`~~ ✅ Исправлено 20.10.2026

**Файл:** строки 3427–3428 (оригинал) → строка 3429 (после правки)

**Проблема:** Подсчёт количества кофейни использовал собственный regex с ленивым квантором `[\d\s\u00A0.,]+?` вместо уже существующей функции `quantity()`. При строке «Кофейня — 12 шт.» пробел мог быть считан как разделитель, и число обрезалось. Дополнительно: строка «Кофейня» без явного числа давала 0 (ветка `if (match)` не срабатывала), тогда как правильный результат — 1.

**Применённое исправление:**
```js
// Было:
const match = item.match(/[-–—]\s*([\d\s\u00A0.,]+?)\s*шт\.?/i);
if (match) coffee += parseNumber(match[1]);

// Стало:
coffee += quantity(item);
```

**Тесты (автоматические, node):** `quantity()` для 1, 2, 12, 20 шт. и строки без числа — 5/5 PASS.

#### ~~Б-2 (ВЫСОКИЙ): Нулевые записи `move` в `analyzeTomorrow()`~~ ✅ Исправлено 20.10.2026

**Файл:** строка 1793 вставлена перед `lasts.forEach`

**Проблема:** Условие `if (need.left <= 0) return` внутри `lasts.forEach` завершало только текущую итерацию внутреннего цикла. После полного удовлетворения потребности обход оставшихся залов продолжался и добавлял записи `move` с `qty: 0`.

**Применённое исправление:**

```js
});
```

**Тесты (автоматические, node):**
- потребность, закрытая на шаге keep → `move[]` пуст — PASS
- частичное покрытие → перенесено ровно нужное qty — PASS
- две независимые потребности — обе обработаны — PASS

### Вероятные ошибки

#### ~~В-3 (ВЫСОКИЙ): Ошибка сдвига времени при бронях после полуночи~~ ✅ Исправлено 20.10.2026

**Файл:** строки ~2008–2023, `getTimeAxis()`

**Проблема:** При расписании с повторяющейся меткой 0:00 (брони после полуночи) логика `while (value <= previous)` могла увеличить `shift` на лишние 1440 минут. Все последующие расчёты `startMinutes` / `endMinutes` оказывались завышены на сутки, что ломало звёздочки первой брони и стрелки переноса оборудования.

**Применённое исправление:** Добавлена проверка повтора по модулю 1440 перед общим fallback:
```js
// Сначала — точное определение «метка вернулась после полуночи»:
while ((value % 1440) === (previous % 1440) && value <= previous && shift < 7 * 1440) {
    shift += 1440;
    value += 1440;
}
// Fallback для нестандартного порядка меток:
while (value <= previous && shift < 7 * 1440) {
    shift += 1440;
    value += 1440;
}
```

#### ~~В-4 (СРЕДНИЙ): Кэш `parseCard()` не инвалидируется при смене зала~~ ✅ Исправлено 20.10.2026

**Файл:** строки ~1865–1870

**Проблема:** Ключ кэша строился только из `.textContent` меток `.reserve-phone-label`. Если изменилось только название зала (другое поле карточки), кэш не сбрасывался и `info.hallFull` возвращал устаревшее значение.

**Применённое исправление:**
```js
const hallText = card.querySelector('.reserve-title-label')?.textContent || '';
const cacheKey = labels.map(l => l.textContent).join('\u0001') + '\u0001' + hallText;
```

#### ~~В-5 (СРЕДНИЙ): `getCategoryFromBranch()` возвращает null при отсутствии aria-атрибутов~~ ✅ Исправлено 20.10.2026

**Файл:** `update()`, ~строка 4640

**Проблема:** Если оба элемента «Павелецкая» и «Серпуховская» видимы и имеют score=0 (нет aria-selected/aria-pressed), функция возвращала null и `categorySource` оставался `'default'` (С). Это вело к неверному расчёту для Павелецкой при любом обновлении интерфейса Bitrix.

**Применённое исправление:** В `update()` добавлена ветка `else if (categorySource === 'default')`, явно вызывающая `inferCategoryFromRecords()` — определение филиала по суффиксам залов из уже загруженных записей:
```js
if (detected === 'C' || detected === 'P') {
    setCategory(detected, 'branch');
} else if (categorySource === 'default') {
    const inferred = inferCategoryFromRecords();
    if (inferred) setCategory(inferred, 'halls');
}
```

### Этап 10 — Срочное исправление регрессии 4.3.0–4.5.0 (24.10.2026; hotfix 4.5.1 выпущен, остальные пункты — в плане)

**Симптомы (со слов пользователя + отчёт «Диагностика» от 24.10.2026, версия 4.5.0, Safari 27, филиал «Павелецкая», 27 броней):**
интерфейс плагина пропадает после действий с карточкой брони (после обновления страницы возвращается); не меняются цвета стадий; «не работают кнопки».

**Причина найдена по отчёту** (в журнале ошибок iframe-сборщика: `ReferenceError: Cannot access 'settingsChanged' before initialization`) и подтверждена чтением кода: в обработчике сообщений сборщика (`startCollector()`, версия 4.3.0) переменная `settingsChanged` присваивается внутри блока `if (event.data.settings)` раньше, чем объявлена через `let` (строкой ниже, рядом с `marksChanged`) — ошибка «временной мёртвой зоны». Срабатывает только если настройки в iframe отличаются от пришедших со страницы, то есть **когда пользователь изменил любую настройку или цвета** (в отчёте цвета стадий не по умолчанию). Тогда обработчик падает до `applyFeatures()` и до ответа `send(...)`:
- цвета и переключатели не применяются в календаре (`features` уже заменены, а применение не вызвано);
- сборщик перестаёт отвечать на запросы, данные перестают приходить, и после действий с бронью срабатывает скрытие интерфейса («карточек нет»), которое некому снять — отсюда исчезновение панели;
